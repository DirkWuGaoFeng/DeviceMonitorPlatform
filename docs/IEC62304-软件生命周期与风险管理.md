## 1. 软件描述

- **软件名称/预期用途**：多仪器数据采集与监控上位机软件（DeviceMonitorPlatform），用于连接检验/监护类设备，实时显示测量值、越限时产生危急值告警并存储历史记录。（个人作品集/技术演示，**不用于真实临床诊断**）
- **软件功能**：设备接入、数据采集/解析、实时显示、阈值告警、历史存储与回放、导出、后端服务化（文本 API / gRPC）、运维诊断归因。
- **接口**：下位机 UART(TCP 模拟或真串口)/帧协议见 `frame_protocol.h`；数据库 SQLite；北向 gRPC `proto/telemetry.proto` 与文本行网关 `service_proto.h`。
- **开发/验证环境**（用于构建与取证，**不承诺交付**）：Windows 10/11 + MinGW（Qt 6.10.0 mingw_64）；WSL2 Ubuntu —— **仅作构建 / 工具链沙箱**（apt 版 gRPC/protoc、pkg-config 探测、Linux 编译验证）；VM Ubuntu 22.04 + ROS2 Humble（ROS2 桥与跨机真板验收）；GitHub Actions（Linux gcc Release/Debug + Windows MSYS2 MinGW）。
- **目标运行环境**（交付形态，须能写入 POUD/SOUP 论证）：Windows 10/11 **IoT Enterprise LTSC**（Qt 上位机 + 原生串口，已做实）；原生 **Ubuntu 22.04 LTS** 或信创发行版（银河麒麟 / 统信 UOS，网关与 gRPC/ROS2 服务侧）；厂商 BSP 的嵌入式 Linux（床旁设备 / HMI）；嵌入式目标 STM32F103（HAL）。
  > **WSL2 不作为交付运行环境**：非厂商支持配置（无法提 support case）、无 `PREEMPT_RT` 且 `SCHED_FIFO` 不保证、服务生命周期随 WSL 会话回收、双层时钟同步、USB 串口须经 `usbipd-win` 打洞（热插拔节点名漂移、`dialout` 权限随版本变）、`/mnt/e` DrvFs 跨文件系统 I/O 与 SQLite WAL 锁语义风险 —— 故**不进 POUD 清单**。详见 `docs/网关与服务链路优化方案.md` §2 非目标。
- **环境口径变更的追溯影响**：R-005 的成因一栏原列“WSL↔Windows 网络抖动”，现 WSL 已退出链路一环，该成因改述为“跨机 TCP 抖动”；Linux 侧验证统一以原生 VM/实体机为载体（SR-016）。
- **开发框架/过程模型**：自研 V 模型（需求→架构→单元设计→单元/集成/系统验证），文档与代码同仓演进，自动化回归由 GitHub Actions 承担（详 §3/§6/§9）。
- **是否 SaMD / SiMD**：含 **SiMD** 边界（`firmware/` 为器械嵌入式软件一部分，与器械协同运行）与 **SaMD** 边界（上位机/网关/gRPC/Agent 为独立数据处理软件）；本项目作为能力展示同时讲清两侧接口如何以帧协议契约隔离。

## 2. 软件安全分级（IEC 62304 5.1）

> 分级依据：软件失效是否可能导致伤害。A=无伤害；B=非严重伤害；C=死亡/严重伤害。

| 软件项/模块 | 危害分析 | 安全等级 | 说明 |
|---|---|:--:|---|
| 帧解析 / 数据链路 | 丢帧/错值 → 误读测量 | B | 数据完整性失效可能导致错误判断 |
| 危急值告警 | 告警漏报/延迟 → 延误处置 | C | 安全关键，最高级 |
| 数据显示 UI | 显示错误 → 误判 | B | |
| 历史存储 | 记录丢失 → 追溯缺失 | B | 影响不良事件回查，非直接伤害 |
| 运维诊断 Agent | 误诊建议误导运维 | A | 只读网关 STATS/ALARMS/HISTORY，输出仅作运维参考、**不进入任何控制回路**，失效不直接致伤害，故定最低级 |

- 安全等级 A 可免完整生命周期控制；B 需 5.3/5.6/5.7/5.8（部分）；C 需 5.3/5.6/5.7/5.8（增强）+ 7.3。
  本项目实际裁剪与其理由已集中记录于 **§3 策划末尾**（一句话：保留追溯/验证/风险三项做实，省略独立 QA 与生产/退市过程）。

## 3. 策划（5.2）

- **生命周期模型**：V 模型（左翼需求→架构→单元设计，右翼单元验证→集成→系统验证），文档与代码同仓演进；个人作品无独立 QA 组织，采用“开发兼验证 + 自动化测试作客观证据”的最小裁剪。
- **开发活动与任务**：按 README 落地路线 1~9 逐条推进，每条以“可编译 / 可跑 / 有断言证据 / 文档回填”为完成定义（DoD）。
- 已知/预计风险与缓解【见第 8 节 R-001~006，每项控制措施均绑定一个可追溯验证条目】
- 验证与确认策略【第 6/7 节】
- **缺陷管理**：以仓库 Issue + 本档 §6 “CI 暴露缺陷登记”记录，并逐条沉淀到 `docs/经典Bug素材录.md`（49 条：现象/误判路径/根因/修复/可讲点；§7 专记生命周期与组件化的 11 条，含**被实测推翻的架构理由**；§8 记毒化实验、验收护栏与下游联动（c13~c17、e1）的 13 条，含**取证工具自己骗自己**的两个新变种、一个**诊断工具自己分辨不开成因**的变种、一个**取证动作把犯罪现场冲掉**的变种，两个**把"已设计"当成"已实跑/已提交"**的变种（二手笔记与卡死终端都会交出看上去执行过的假象），加第三个同族变种——**提交动作成功而提交载荷是上一版**（README 目录树引用了一个 untracked 文档，而 CI 全绿不能区分两者，B-49），以及**把自己量出的规律外推到生态工具**、**用错机制制造前置条件**、**负向测试自己无效**三个新变种）。已定位并回归的真实缺陷含：Qt 构造期空指针、串口路径反斜杠、固件采样相位锁死、CMake 静默跳过 `.c`、缺 `arpa/inet.h`、测试硬依赖子目录、`select(0,…)` 的 POSIX 语义差异（“连接正常、零字节”）、QoS 改副本静默 no-op、`--verify` 拿绝对行数做断言（不可重跑）、CI 装 Qt 少一个模块（本地无法复现的环境差异）。
- 配置管理与维护【第 9 节】
- 风险管理按 ISO 14971 实施（引用）
- **裁剪理由（最小可用生命周期过程的选择）**：无临床/注册用途，故省略 5.1 独立 QA 体系与 7.x 生产/退市过程；但保留并做实对岗位最有说服力的三项——**需求↔测试双向追溯（§10）、单元与集成验证（§6）、风险管理（§8）**。

## 5. 架构与详细设计（5.4 / 5.5）

- **分层**：L1 设备层（`firmware/` STM32 固件 或 `device_simulator`）→ L2 采集协议层（`frame_protocol.h` 解帧 / `ring_buffer.h` 无锁缓冲 / `acquisition.h` 告警与 Sink 抽象 / `pipeline.h` 线程化）→ L3 消费与服务层（`qt_monitor.cpp` UI、`storage.h` CSV/SQLite、`gateway_service.cpp` 文本 API、`service/grpc_server.cpp` gRPC）→ L4 运维智能（`tools/dmp_agent.py`）。（见 architecture.md）
- **单元划分与关键接口**（每个头文件即一个可独立编译/测试的单元）：

| 单元 | 对外接口（契约） | 安全等级 | 验证 |

## 7. 确认（Validation）
