# DeviceMonitorPlatform 架构设计

## 1. 目标

一条端到端数据链，覆盖"下位机/仪器 → 采集 → 实时监控 → 告警 → 存储 → 智能运维"，
用同一套代码同时证明三类岗位能力：**医疗/仪器上位机**、**设备平台/中间件**、**AI 运维 Agent**。

## 2. 分层与数据流

```
┌───────────────────────────────────────────────────────────────┐
│  L1 设备/下位机层   device_simulator.cpp (开发期) / STM32+传感器 (目标)  │
│                     按 dmp 帧协议经 UART/TCP 上报                       │
└───────────────────────────┬───────────────────────────────────┘
                            │ raw bytes
┌───────────────────────────▼───────────────────────────────────┐
│  L2 采集/协议层     include/dmp/frame_protocol.h  帧同步/CRC/粘包拆包   │
│                     include/dmp/ring_buffer.h      无锁环形缓冲解耦     │
│                     include/dmp/acquisition.h      解码→缓冲→告警→Sink  │
└───────────────────────────┬───────────────────────────────────┘
              ┌─────────────┴─────────────┬──────────────────┐
┌─────────────▼───────────┐ ┌─────────────▼────────┐ ┌───────▼──────────────┐
│ L3 UI (qt_monitor.cpp)  │ │ L3 存储 (SqliteSink) │ │ L3 服务层 (规划)      │

│ 采集线程与UI线程分离     │ │ CSV 导出             │ │ FiberMaintain 架构)   │
```

## 3. 关键设计决策

| 决策 | 取舍 | 理由 |
|---|---|---|
| 二进制帧 + CRC16 而非 JSON | 省带宽、贴 MCU | 设备通信链路真实约束；演示粘包拆包 |
| 无锁 SPSC 环形缓冲 | 满时计数/背压 | 采集/UI 解耦，热路径不加锁 |
| Sink 抽象接口 | 多一个间接层 | 存储/推送可插拔(SQLite↔gRPC↔WS) |
| 阈值告警回调注入 | — | 危急值策略随设备配置变化 |
| 采集与 UI 分线程 + drain 批量 | 略增延迟 | 20fps 刷新不阻塞解析 |

## 4. 帧协议

见 `include/dmp/frame_protocol.h`。12 字节定长帧：`AA 55 | seq(u16) | channel(u8) | type(u8) | value(f32) | crc16`。

## 5. 演进路线（对应 8 周计划 W3-5）

1. 模拟器换 STM32/UART（协议不变，替换 L1）
2. 真实采集线程 + 背压策略（L2 完善）
3. SQLite 历史 + 回放 + CSV 导出（L3 存储）
4. 抽取 gRPC 服务层，多设备并发纳管（L3 服务，复用 FiberMaintain）
5. LLM 运维 Agent 接入（L4，复用 Agent-Fiber）
6. 按 IEC 62304 补齐可追溯矩阵 + 风险分析（见同目录合规文档）
