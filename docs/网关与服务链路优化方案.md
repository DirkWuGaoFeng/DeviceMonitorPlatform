## 0. 摘要

本方案解决一个核心矛盾：**当前多个消费者在逻辑上独立、在物理上串在同一个线程上**。

`gateway_service` 已经具备"1 个上游 → N 个消费者"的扇出能力，且同一份 `Acquisition` 解码内核已在
Windows / 原生 Linux（VM）两处复用（WSL2 已退役）。但事件循环是单线程 `select`，而 `sendAll` 跑在**阻塞 socket** 上——
任一下游网络抖动即可卡死主循环，连带串口 `ReadFile` 停摆、驱动缓冲溢出**真丢字节**，从而污染全部消费者。

四个目标：① 把"消费者独立"做到线程与队列层；② 消除 COM 口争用，让真机 + Qt 画面 + gRPC + ROS2 + Agent
同场共存；③ 让网关在**原生 Linux** 上成为一等公民；④ 支持一台主机接入多台仪器。

**本方案明确不声称 epoll 带来吞吐收益**（§2 非目标），动机是正确性与部署形态。

## 2. 目标 / 非目标

### 目标

- **G1 物理隔离**：任何单个消费者的故障不得影响其它消费者与采集节拍。
- **G2 消除串口争用**：真机 + Qt 画面 + gRPC + ROS2 + Agent 五者同场。
- **G3 原生 Linux 一等公民**：直连 tty、事件驱动、可产品化部署。
- **G4 多设备纳管**：一台主机接多台仪器。
- **G5 分段归因**：把"哪一段丢的"做到可断言（同时加固 R-005 / R-007 的验证证据）。

### 非目标（含明确否决理由）

| 否决项 | 理由 |
|---|---|
| ❌ 以 **WSL2 为运行环境** | 进不了 POUD/SOUP 论证：非厂商支持配置、无 `PREEMPT_RT`、`SCHED_FIFO` 不保证、服务生命周期随会话回收、双层时钟同步、`/mnt/e` DrvFs 跨 fs I/O 与 SQLite WAL 锁语义风险、USB 须经 `usbipd-win` 打洞（热插拔节点名漂移、`dialout` 权限随版本变）。**WSL2 已从环境清单完全退役**（连构建 / 工具链沙箱职责也并入原生 VM）；Linux 目标环境 = 原生 Ubuntu 22.04（VM 或实体工控机） |
| ❌ 以 **epoll 提升吞吐**为动机 | 本负载 4ch×5Hz ≈ 240 B/s、客户端 2~4 个，**select 的 O(n) 扫描与 1024 上限均碰不到**，无可测差异。依项目测试规范（结论须由本轮数据现算、A/B 只比同组配对差），**禁止在无实测依据时声称性能收益** |
| ❌ Qt 订阅 ROS2 `/dmp/frames` | 违反既有决策"Qt 与采集进程内直调，不走 RPC"；且把 UI 可用性绑到 DDS + 跨机链路，链路一抖 UI 无数据 |
| ❌ 修改 12 字节帧协议 / 加 `END` 帧 / 加 device 信封 | `RAW` 的既有契约是"逐字节透传不重组"，这是下游 `crc_err` 可归因的前提；加信封会破坏 WSL 与 VM 两条已验链路，并触发协议变更规则（须重跑 `test_frame_parity` 金标准帧 + 真机链路） |
| ❌ 合并各段丢弃计数 | 合并会掩盖是哪一段丢的（延续 `ros2/README.md` "故意不合并"的既有决策） |
| ❌ 共享内存 / rosbridge 替代同机 TCP 透传 | 省的是 240 B/s，不是瓶颈；复杂度与跨 VM 网段失效不抵收益 |
| ❌ 把两套事件循环抽象成最小公倍数 | `select` 是 Windows 唯一可移植复用机制，`WSAEventSelect` 不比它好。沿用 `#ifdef _WIN32` 显式写开语义差异 |

## 3. 优化项明细

### M1（P0）慢客户端隔离 + Qt 接入网关

#### T1.1 每客户端有界发送队列

**方案**

- 新增 header-only 模块 `include/dmp/outbound_queue.h`：**不依赖 socket** 的纯函数类
  ```
  OutboundQueue {
      bool   push(std::string, size_t capBytes);  // 满则丢最旧并计数
      bool   empty() const;
      size_t pump(sendResult fn);                 // 尽力排空, 返回本次发出字节
      size_t droppedBytes() const;  size_t droppedMsgs() const;
  }
  ```
  内部 `std::deque<std::string>` + 字节上限，**满时丢最旧并计数**（沿用 `ring_buffer.h` 的有界丢弃哲学）。
- `Client` 增加 `OutboundQueue outq;`，常量 `kOutqMaxBytes = 256 * 1024`。
  **上限的时间口径（v1.1 复核改写）**：240 B/s 是 RAW 帧流（12 B/帧 × 4ch × 5Hz），所以 256 KB ≈ **18 分钟** RAW；
  文本行订阅者按 `formatSample` 的格式串数出来约 **60 B/样本**（`SAMPLE ts=` 10 + 13 位毫秒 + ` seq=` 5 + ~7 位 + ` ch=` 5 + ` type=` 7 + ` name=` 2~5 + ` value=` 7 + 6 + `\n`）
  × 20 样本/s ≈ **1.2 KB/s ⇒ 256 KB 只顶得住 ≈3.5 分钟**，比 RAW 的 18 分钟敏感得多。
  原写“≈10 分钟 RAW 流”不准。**正因为两类订阅者的字节速率差一个量级，失能水位必须按“秒”定而不是按“字节”定**（见下面双条件）。
- **出向只有一个出口（v1.1 定案，B-1）**：同一连接上**所有**出向字节——广播**和**命令应答——只能经该连接的队列。
  13 个 `sendAll` 调用点里只有 3 个是广播、**10 个是应答**；若只改广播、应答仍直发，应答字节会**插到已入队的订阅数据前面**：
  文本行是行序错乱，RAW 则是 `+RAW\n` 三字节混进帧流中间（下游当帧内容解 ⇒ `crc_err` 尖峰）。
- `sendAll` → `pumpNonBlocking(c)`：fd 设 `O_NONBLOCK` / `ioctlsocket(FIONBIO)`；单轮最多排空 64 KB；
  `EAGAIN` / `WSAEWOULDBLOCK` 视为"稍后再试"（**不是错误**）；`EINTR` 重试；`EPOLLERR/HUP` 或真错误才断连。
  **同时钉死读路径语义（v1.1 新增）**：fd 置非阻塞后 `recv` 会返 `EAGAIN`，而现 L235 的 `if (n <= 0) { CLOSESOCK; erase; }`
  会把**正常空读当成对端关闭**——该缺陷今天不存在（阻塞 socket），是本改造制造的。
- **丢弃策略按客户端类型分流（v1.1 定案，B-2）**：
  - 文本行订阅者：可整条消息丢（行协议自带边界，丢一条不影响后续解码）。
  - **RAW 订阅者：宁可踢除也不丢半帧**——在字节流中间掉一段会强迫下游靠帧头重同步，而 `crc_err` 尖峰污染的正是要做的归因。
- 失能处置改为**双条件 + 分类型（v1.1 定案，B-3）**：`队列满` **或** `积压水位 > 30 s 数据量（RAW ≈7 KB）`，任一成立即判失能（后者先触发；原定的“连续 3 次排空仍满”要 18 分钟才发现，而这 18 分钟里主循环每轮都在替它排队）。
  - 有重连能力的下游（VM 桥：`reconnects()` 已在 `/diagnostics` 上可读）→ `CLOSESOCK` 踢除，打印
    `[gateway] client evicted: reason=%s dropped=%llu`。**踢除优于拖累全体。**
  - **无自动重连的客户端（Qt / `QTcpSocket`，见 P3）→ 不踢**：置 `stalled`、停止入队但保留连接，追上后续传。踢掉它等于 UI 静默冻结，比丢几帧更糟（§6 “静默无数据”那行原只盖了 connect 阶段）。
- **P8 改写（v1.1 定案）**：不是“把 `LASTWSAE()` 的 POSIX 分支改成 `errno`”——`LASTWSAE()` **全仓无调用点，两条腿上都是死代码**，改完仍然死。
  真动作是 **`sendAll` 返回错误类别枚举**（`Ok / WouldBlock / PeerClosed / ProtoError / LocalErr`），POSIX 取 `errno`、Windows 取 `WSAGetLastError()`，并把类别计数并进 `STATS`；G5 分段归因需要的是这个字段，不是那个宏。

**验收判据**

- 新增 `tests/test_outbound_queue.cpp`（CHECK 宏风格）断言 **≥15 项**：有界性、溢出丢最旧、
  **字节守恒**（pushed == sent + dropped + queued）、FIFO 保序、空队列不越界、失能判定条件、
  **非空队列不丢尾**、`WouldBlock` 不计为错误。这一部分**入 `ctest`**，随 CI 三条腿跑。
- 新增 `tools/slow_client_probe`：一个故意读完即 `sleep` 的慢客户端 + 一个正常客户端。**判据**：
  正常客户端 `crc_err=0`、`seq` 连续；三段丢弃中仅 `queue` 段对慢客户端增长；慢客户端被判失能（踢除或 `stalled`，按类型）。
  **结论行必须由本轮数据现算**（不得写死）。
- **归因要找一个不是自己写的证人（v1.1 新增，B-2）**：慢客户端的 `queue_drop` 字节数，要由下游**独立算出的 seq gap** 复核：
  `gaps = last_seq - first_seq + 1 - received`。前提是先确认**上游 `seq` 连续发号**（`device_simulator` 与固件 `dmp_task()` 均要查；
  若 `seq` 上电从 0 重启，一次重连会被读成一个大洞）。只把网关自己的三个计数器相加，等于自证。
- **量“丢了多少”而不是“有没有丢”（v1.1 新增，P2）**：115200 8N1 ≈ 11.5 KB/s、驱动接收缓冲典型 4–12 KB
  ⇒ 主循环停 **0.35–1 s** 就溢出。判据里要给字节数与 seq 数，不只给布尔值。
- **探针不进 CI 门禁（v1.1 定案）**：分钟级时序断言上 CI 必然 flaky。`slow_client_probe` 走 VM / 本地实跑，
  原始读数落 `tools/diagnostics/evidence/`（与 §8 第 5 条一致）。

**影响面**：Windows / Linux 双腿同改；VM 上的 ROS2 桥与原生 `grpc_server` 作为 RAW 订阅者**行为兼容**（只增队列，线格式不变）。

**实况（2026-09-30 T1.1 第二步落地，与上面方案文本的有意偏离，均以实测为准）**

- **默认水位**：`Params` 取 `capBytes=64 KB / hi=48 KB / lo=16 KB`，**不是方案写的 256 KB**。理由正是方案自己那条“失能水位按秒定不按字节定”：文本订阅 ≈1.2 KB/s ⇒ 64 KB ≈ **53 s**、越 hi(48 KB)≈40 s 即入 `stalled`，落在“积压 > 30 s 判失能”的口径内；256 KB 反而会把发现失能拖到 ≈3.5 分钟。
- **新增 `--sndbuf`（内核发送缓冲上限）**：本机实测 Linux 环回“对端一字节不读能连写多少”默认高达 **2,703,360 B**（`probe_bufcal.py`），只在应用层设 64 KB 队列等于没设——慢客户端先被内核缓冲喂饱、根本不触发队列丢弃。**有界内存的真实上界 = 应用层队列 + 内核 `SO_SNDBUF`**，故网关 accept 时对每连接 `setSendBuf`。
- **`STATS` 行格式不改，另增 `CLIENTS` 命令**：每连接报 `id/sub/raw/qbytes/lines/stalled/enq/sent/drop/evict/kick`，慢客户端归因靠它；不挤进 `STATS` 是为了不破坏既有下游对该行的解析。
- **B-2 以 `keepStreamIntact` 兑现**：策略做进纯函数模块（`requireStreamIntact(bool)` 可在 RAW 订阅时后置开启——重建队列会清掉累计计数，而 `CLIENTS` 报的是累计量，不能中途清）。开了它**从不挤位**，装不下只 `kickNeeded++`（含“整块比上限还大”的必洞情形）；网关在 `case K::Raw` 开启。单测 `test_stream_intact` + 探针 J10 实测到“被踢除而非被打洞”（`evict==0 && kick>=1`）。
- **P8 五类错误枚举有意缩水**：本轮最小必须集只需区分“稍后再试（`wouldBlock`）”与“真断开（`dead`）”两类——非阻塞 `recv` 空读不断连、`send` 返 `EWOULDBLOCK` 不算错，这两条已覆盖 B-3 的失能分流。`Ok/WouldBlock/PeerClosed/ProtoError/LocalErr` 五类计数是 G5 分段归因的字段，**有意留待后续**，不在 T1.1 硬凑。

#### T1.2 Qt 经网关取数（RAW 握手）

**方案**

- `qt_monitor` 源下拉新增第三项 **"网关 (TCP RAW)"**：`connected` 后写一行 `RAW\n`，收到 `+RAW\n`
  后丢弃该握手回显，其余字节交现有 `onBytes()` 解码。改动局限在传输层，复用既有
  `Acquisition` / `TeeSink` / `SqliteSink` / 曲线全链路。
- **阈值权威归属（§7-1 决策 1 已定案，本项已实施）**：**Qt 为配置权威** —— 进入 RAW 透传前，Qt 先在命令态
  依次下发本地 3 条 `RULE`，再 `RULES` 回读逐条比对 `low/high`（回读块以 `HELP` 应答作屏障界定结束）；
  不一致则状态栏标红并**拒绝进入“已连接”态**（网关对 `low>=high` 的 `RULE` 拒绝生效、保留原值，回读即暴露分歧）。
  理由：复用已有 `RULES/RULE` 面与 SR-012 的"网关侧独立回读核对"断言；把"两个解码器各持一份阈值"
  显式收敛为单一权威，而不是靠"约定它们相同"。
- **效果**：COM4 由网关独占，Qt / 桥 / gRPC / Agent 全走 TCP ⇒ 拓扑 A 与 B 合并，
  `run_*_serial.ps1` 中的互杀逻辑可退役（P4 关闭）。

**验收判据**

- 新增 `qt_monitor --verify-gateway <host> <port> <ms>`（无头、不依赖事件循环）：断言
  **(网关 `STATS.ok` 本轮增量) == (Qt 本地解码条数)**，且 `crcErr == 0`、**阈值回读一致**（stats 命令腿下发
  本地 `RULE` 集 + `RULES` 回读 + `HELP` 屏障，逐条比 `low/high`，输出 `thrBad=` 计数并入 PASS 判据）。
  沿用 `runVerify()` 的"取增量、不取绝对值"口径——早期拿 `COUNT(*)` 绝对值导致自检只有空库才可能通过（已记录）。
- 手工：`run_gateway_serial.ps1` + Qt 选"网关 (TCP RAW)" → 曲线滚动、告警可触发、SQLite 落库增长。

### M3（P1）原生 Linux 网关（termios + epoll）

**目标环境（写死，防口径漂移）**：原生 Ubuntu 22.04 LTS（glibc + systemd）；验证载体为已有 VM，
产品形态为实体工控机 / 厂商 BSP 的嵌入式 Linux。**WSL2 不在运行环境清单内。**

#### T3.1 分步实施（顺序即风险控制）

| 步 | 内容 | 新代码量 |
|---|---|---|
| **S1** | **Linux TCP 上游模式实跑**（零新代码，纯验收） | 0 |
| S2 | `--serial` 的 Linux 分支：termios + 端口识别 | 小 |
| S3 | POSIX 侧事件循环换 epoll（**依赖 T1.1 已完成**） | 中 |
| S4 | VM 上重跑 `vm_realdevice_e2e.sh` 同套判据（脚本加 `GATEWAY=linux` 开关） | 0 |

- **S1 必须先做**：这是纯证伪动作。项目历史上最贵的 bug 即在此带——`select()` 的 `nfds` 在 Windows 被忽略、
  POSIX 必须为 `max_fd+1`，传错则"连接正常、`dataUp()==true`、零字节"。当前 L201 的
  `static_cast<int>(nf)` 静态看是对的，**但必须实测，不得靠读代码确认结论**。
- **S2 细节**：`open(path, O_RDWR | O_NOCTTY)` + `tcgetattr/tcsetattr`；`cfmakeraw`；
  `cfsetispeed/ospeed(B115200)`；`c_cflag |= CREAD|CLOCAL`；`VMIN=0, VTIME=1`（100ms 有界读，
  让"无数据"成为可读事件而非挂死）。`normalizePort` 的 POSIX 分支识别 `/dev/tty{ACM,USB,S}*`，
  **不做** `COM4→/dev/ttyS3` 伪映射。部署说明须含 `dialout` 组与 `udev` 固定别名（防热插拔节点漂移）。
- **S3 细节**：`epoll_create1(EPOLL_CLOEXEC)`；tty / listener / client 注册 `EPOLLIN | EPOLLET`；
  client 出向非空时 `EPOLL_CTL_MOD` 加 `EPOLLOUT`，排空后**摘除**（否则忙轮询）。
  ET 的前置义务：fd 必须非阻塞、每事件循环处理至 `EAGAIN`、`accept4(SOCK_NONBLOCK)`、
  `EPOLLHUP|EPOLLERR` 走清理路径。Windows 侧 select 腿**原样保留**。

**验收**：Linux 网关 + VM 桥 + gRPC 三者同场；`vm_realdevice_e2e.sh` 六项检查全绿
（`/dmp/frames` 有真帧、`/diagnostics` `crc_err=0`、发布 QoS `BEST_EFFORT` **实测**非推断、
`set_rule` 后网关侧独立回读、非法区间被拒、`selftest healthy=True`）。

**收益定位（不得夸大）**：G3 的价值 = 部署形态成立 + 去掉轮询节拍 + **ET 从机制上强制出向队列正确**；**不含吞吐主张**。

## 6. 风险与回退

| 风险 | 缓解 |
|---|---|
| 非阻塞改造引入"发送丢尾 / 半行" | 线格式（`service_proto.h` 的 `format*`）**零改动**，58 项既有断言继续守护；新增字节守恒断言 |

| epoll ET 编程出错 | 出向队列先于 epoll 落地（T1.1 独立可测）；`EPOLLOUT` 仅在队列非空时注册；慢客户端注入用例专门覆盖 |
| 多设备端口方案的运维成本 | 写入 ADR-005 的失效条件（机队 >10 台须重新论证） |
| 阈值双权威（Qt 与网关各持一份）造成判定漂移 | §7-1 定为单一权威 + 回读不一致即不进连接态 |

### 10.2 三处会返工的设计缺口

**B-1｜出向只有一个出口，命令应答也必须入队**
T1.1 只写了“上游来字节 → 入队”。但 `sendAll` 的 13 个调用点里 **10 个是命令应答**（剩下 3 个才是广播）。若只把广播改成非阻塞入队、应答仍直发，应答字节会**插到已入队的订阅数据前面**：文本行订阅者看到的是行序错乱，RAW 订阅者则会把 `+RAW\n` 这三字节**混进帧流中间**，下游当帧内容解 ⇒ `crc_err` 尖峰。
⇒ 设计约束明写：“**同一连接上所有出向字节只有一个出口 = 该连接的出向队列**”。否则 T1.1 的“字节守恒”断言会直接红，而且红了容易被当成队列 bug。

**B-2｜“满则丢最旧”对 RAW 流是破坏定界的，而且这个丢法必须找一个不是自己写的证人**
RAW 的既有契约是逐字节透传不重组（本文 §2 非目标自己写的）。在流中间掉一段，下游解码器只能靠帧头重同步，代价是 `crc_err` 尖峰——**它污染的正是要做的归因**。
好消息：`sample.seq` 在帧内（`DeviceFrame`/固件内核同源），**下游可以独立算出丢了几个号**：`gaps = last_seq - first_seq + 1 - received`。所以归因等式成立的前提要补两条：
1. **慢客户端的 `queue_drop` 必须由下游 seq gap 独立复核**，不能只把网关自己三个计数器加起来自证（延续“换一个不是我写的证人”的既有纪律）；
2. 先确认 **seq 上游是否连续发号**（含固件重发/上电重置）——若 `seq` 会从 0 重启，一次重连的 gap 会被读成一个大洞。本方案 §1.1 把固件与上位机列为同源，但未校 seq 重置语义。
⇒ 处置建议：**RAW 与非 RAW 分流**。文本行可以整行丢；RAW 宁可**踢除也不丢半帧**（踢除后下游重连从新边界开始，不产生坏字节）。

**B-3｜踢除阈值的量纲选错了，而且对 Qt 不该踢**
按 256 KB / 240 B/s 算，队列从空到满要约 **18 分钟**。“连续 3 次排空仍满”确实不会被一次 GUI 卡顿误伤（这点方案是安全的）；但反过来——**它要 18 分钟才发现慢客户端**，而这 18 分钟里主循环每轮都在替它排队。真正该盯的不是“队列满”，是**积压水位代表多少秒的数据**。
⇒ 建议改成双条件：`队列满` **或** `积压 > 30 s 数据量（≈7 KB）`，后者先触发；参数扫描用 `slow_client_probe` 定（正好是 §7 决策 2 里的“真实抖动重标定”）。
⇒ 且按客户端类型分流：**Qt 不会自动重连**（P3 已核），踢掉它 = UI 静默冻结，比丢几帧更糟（§6 那条“静默无数据是已记录的同族 bug”只盖了 connect 阶段，没盖**中途被踢**）。建议：非 RAW 文本客户端（UI 类）积压超限时置 `stalled`、**停止入队但保留连接**，追上后续传；RAW / 无重连能力的客户端才踢。这一条要写进 §7 决策 2 定案。
