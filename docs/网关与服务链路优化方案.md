## 0. 摘要

本方案解决一个核心矛盾：**当前多个消费者在逻辑上独立、在物理上串在同一个线程上**。

`gateway_service` 已经具备"1 个上游 → N 个消费者"的扇出能力，且同一份 `Acquisition` 解码内核已在
Windows / WSL2 / VM 三处复用。但事件循环是单线程 `select`，而 `sendAll` 跑在**阻塞 socket** 上——
任一下游网络抖动即可卡死主循环，连带串口 `ReadFile` 停摆、驱动缓冲溢出**真丢字节**，从而污染全部消费者。

四个目标：① 把"消费者独立"做到线程与队列层；② 消除 COM 口争用，让真机 + Qt 画面 + gRPC + ROS2 + Agent
同场共存；③ 让网关在**原生 Linux** 上成为一等公民；④ 支持一台主机接入多台仪器。

**本方案明确不声称 epoll 带来吞吐收益**（§2 非目标），动机是正确性与部署形态。

## 1. 问题陈述（以代码事实为准）

| # | 现状 | 证据 |
|---|---|---|
| P1 | 多消费者共享**同一单线程 `select` 事件循环**；`sendAll` 在**阻塞 socket** 上循环 `send` | `gateway_service.cpp` L64-L72、L194-L221 |
| P2 | 任一慢客户端阻塞 → 主循环停摆 → `ReadFile` 无人调用 → 串口驱动溢出**真丢字节** | 同 L204-L213 循环体 |
| P3 | `qt_monitor` **无法**从网关取数：网关对新连接不推数据，须先发 `RAW\n` 才置 `c.raw`；Qt 无此握手 | L256-L257；`qt_monitor.cpp` L379 |
| P4 | 串口独占 ⇒ 两条拓扑**互斥**，启动脚本互相杀进程释放 COM 口 | `run_gateway_serial.ps1` L10-L14、`run_qt_serial.ps1` L12-L14 |
| P5 | `--serial` 只认一个端口，`g_ser` 为全局单句柄；真实上位机需一台 PC 混接多台仪器 | L76、L114-L137 |
| P6 | 帧 `stamp` 用 `system_clock`、ms 精度，未区分单调钟（ADR-001 已列为遗留项） | `nowMs()` L46-L49 |
| P7 | 丢弃计数仅两段（网关 `dropped` / 桥 `bridge_dropped`），无法区分"串口溢出 / 网关环满 / 客户端队列满" | `Client` 结构无出向队列 |
| P8 | `LASTWSAE()` 在 POSIX 分支被 `#define (0)`，跨平台错误码处理形同虚设 | L43 |

### 1.1 已具备、不需重建的能力

- **扇出已成立**：`std::vector<Client>` + 每客户端独立 `subscribing` / `raw` 标志；广播循环 L210-L212
  今天就支持多个 RAW 订阅者并存（VM 桥与 WSL `grpc_server` 即是两个独立订阅者）。
- **Linux 编译已通过**：`gateway_service.cpp` L27-L44 有完整跨平台 socket 抽象；`CMakeLists.txt` L36-L40
  的 `add_executable` 无平台守卫（`ws2_32` 仅在 `if(WIN32)` 链接）；`ci.yml` linux-gcc 腿 `cmake --build build -j`
  构全 target。**即该文件此刻就在 Linux 上编译链接，只是从未在 Linux 上真正跑过。**
- **桥侧已支持多设备**：服务名带设备段（`/dmp/bed01/set_rule`）、`launch` 传 `device_id`、已验同容器双设备。

> 结论：要改的是**实现强度**（隔离与解耦）与**接入面**（Qt、多设备、原生 Linux），不是架构骨架。

## 2. 目标 / 非目标

### 目标

- **G1 物理隔离**：任何单个消费者的故障不得影响其它消费者与采集节拍。
- **G2 消除串口争用**：真机 + Qt 画面 + gRPC + ROS2 + Agent 五者同场。
- **G3 原生 Linux 一等公民**：直连 tty、事件驱动、可产品化部署。
- **G4 多设备纳管**：一台主机接多台仪器。
- **G5 分段归因**：把"哪一段丢的"做到可断言（同时加固 R-005 / R-007 的验证证据）。

### 非目标（含明确否决理由）

| 否决项 | 理由 |
|---|---|
| ❌ 以 **WSL2 为运行环境** | 进不了 POUD/SOUP 论证：非厂商支持配置、无 `PREEMPT_RT`、`SCHED_FIFO` 不保证、服务生命周期随会话回收、双层时钟同步、`/mnt/e` DrvFs 跨 fs I/O 与 SQLite WAL 锁语义风险、USB 须经 `usbipd-win` 打洞（热插拔节点名漂移、`dialout` 权限随版本变）。**WSL2 在本项目中仅保留为构建 / 工具链沙箱**；Linux 目标环境 = 原生 Ubuntu 22.04（VM 或实体工控机） |
| ❌ 以 **epoll 提升吞吐**为动机 | 本负载 4ch×5Hz ≈ 240 B/s、客户端 2~4 个，**select 的 O(n) 扫描与 1024 上限均碰不到**，无可测差异。依项目测试规范（结论须由本轮数据现算、A/B 只比同组配对差），**禁止在无实测依据时声称性能收益** |
| ❌ Qt 订阅 ROS2 `/dmp/frames` | 违反既有决策"Qt 与采集进程内直调，不走 RPC"；且把 UI 可用性绑到 DDS + 跨机链路，链路一抖 UI 无数据 |
| ❌ 修改 12 字节帧协议 / 加 `END` 帧 / 加 device 信封 | `RAW` 的既有契约是"逐字节透传不重组"，这是下游 `crc_err` 可归因的前提；加信封会破坏 WSL 与 VM 两条已验链路，并触发协议变更规则（须重跑 `test_frame_parity` 金标准帧 + 真机链路） |
| ❌ 合并各段丢弃计数 | 合并会掩盖是哪一段丢的（延续 `ros2/README.md` "故意不合并"的既有决策） |
| ❌ 共享内存 / rosbridge 替代同机 TCP 透传 | 省的是 240 B/s，不是瓶颈；复杂度与跨 VM 网段失效不抵收益 |
| ❌ 把两套事件循环抽象成最小公倍数 | `select` 是 Windows 唯一可移植复用机制，`WSAEventSelect` 不比它好。沿用 `#ifdef _WIN32` 显式写开语义差异 |

## 3. 优化项明细

### M1（P0）慢客户端隔离 + Qt 接入网关

#### T1.1 每客户端有界发送队列

**方案**

- 新增 header-only 模块 `include/dmp/outbound_queue.h`：**不依赖 socket** 的纯函数类
  ```
  OutboundQueue {
      bool   push(std::string, size_t capBytes);  // 满则丢最旧并计数
      bool   empty() const;
      size_t pump(sendResult fn);                 // 尽力排空, 返回本次发出字节
      size_t droppedBytes() const;  size_t droppedMsgs() const;
  }
  ```
  内部 `std::deque<std::string>` + 字节上限，**满时丢最旧并计数**（沿用 `ring_buffer.h` 的有界丢弃哲学）。
- `Client` 增加 `OutboundQueue outq;`，常量 `kOutqMaxBytes = 256 * 1024`（≈10 分钟 RAW 流，足以吸收一次网络抖动；超此即该客户端确已失能）。
- `sendAll` → `pumpNonBlocking(c)`：fd 设 `O_NONBLOCK` / `ioctlsocket(FIONBIO)`；单轮最多排空 64 KB；
  `EAGAIN` / `WSAEWOULDBLOCK` 视为"稍后再试"（**不是错误**）；`EINTR` 重试；`EPOLLERR/HUP` 或真错误才断连。
- 主循环每轮改为：上游来字节 → 解码 / 入环 → **入队**到各订阅者 → 尽力排空。
- 失能处置：连续 **3 次**排空后队列仍满 → `CLOSESOCK` 踢除，打印
  `[gateway] client evicted: dropped=%llu`。**踢除优于拖累全体。**
- 修 `LASTWSAE()`：POSIX 分支改为 `errno`（P8）。

**验收判据**

- 新增 `tests/test_outbound_queue.cpp`（CHECK 宏风格）断言 **≥15 项**：有界性、溢出丢最旧、
  **字节守恒**（pushed == sent + dropped + queued）、FIFO 保序、空队列不越界、踢除判定条件。
- 新增 `tools/slow_client_probe`：一个故意读完即 `sleep` 的慢客户端 + 一个正常客户端。**判据**：
  正常客户端 `crc_err=0`、`seq` 连续；三段丢弃中仅 `queue` 段对慢客户端增长；慢客户端被踢除 ≥1 次。
  **结论行必须由本轮数据现算**（不得写死）。

**影响面**：Windows / Linux 双腿同改；VM 桥与 WSL `grpc_server` 作为 RAW 订阅者**行为兼容**（只增队列，线格式不变）。

#### T1.2 Qt 经网关取数（RAW 握手）

**方案**

- `qt_monitor` 源下拉新增第三项 **"网关 (TCP RAW)"**：`connected` 后写一行 `RAW\n`，收到 `+RAW\n`
  后丢弃该握手回显，其余字节交现有 `onBytes()` 解码。改动局限在传输层，复用既有
  `Acquisition` / `TeeSink` / `SqliteSink` / 曲线全链路。
- **阈值权威归属（关键语义决策，待 §7-1 确认）**：定为 **Qt 为配置权威** —— 连上后 Qt 依次下发本地 3 条
  `RULE`，再 `RULES` 回读逐条比对 `low/high`；不一致则状态栏标红并**拒绝进入"已连接"态**。
  理由：复用已有 `RULES/RULE` 面与 SR-012 的"网关侧独立回读核对"断言；把"两个解码器各持一份阈值"
  显式收敛为单一权威，而不是靠"约定它们相同"。
- **效果**：COM4 由网关独占，Qt / 桥 / gRPC / Agent 全走 TCP ⇒ 拓扑 A 与 B 合并，
  `run_*_serial.ps1` 中的互杀逻辑可退役（P4 关闭）。

**验收判据**

- 新增 `qt_monitor --verify-gateway <host> <port> <ms>`（无头、不依赖事件循环）：断言
  **(网关 `STATS.ok` 本轮增量) == (Qt 本地解码条数)**，且 `crcErr == 0`、阈值回读一致。
  沿用 `runVerify()` 的"取增量、不取绝对值"口径——早期拿 `COUNT(*)` 绝对值导致自检只有空库才可能通过（已记录）。
- 手工：`run_gateway_serial.ps1` + Qt 选"网关 (TCP RAW)" → 曲线滚动、告警可触发、SQLite 落库增长。

### M2（P1）采集与客户端服务解耦

#### T2.1 上游读取线程化

- 把 `ReadFile`（串口）/ 上游 `recv` 移入 `include/dmp/pipeline.h` 的 `ProducerThread<Source>`，
  写入 `include/dmp/ring_buffer.h` 的无锁 SPSC 环；主循环 `drain` 后解码 + 分发。
- 消除 `timeval{0, 20000}` 的 20ms 轮询节拍与主循环的耦合（L200）。
- **所有权纪律**（与 SR-007 一致）：采集线程**只写环**，解码留在主循环，严守 SPSC 单生产者/单消费者，
  不引入第二写者；`FrameDecoder` / `Acquisition` 的持有者必须在注释与断言里钉死。
- Windows 可选增强（**不进 M2 交付**，列为咨询项）：串口改 `WaitCommEvent(EV_RXCHAR)` 事件驱动取代固定超时。

**验收**：`test_pipeline` 既有 9 项断言继续通过；新增 e2e 判据——慢客户端在场时，网关 `STATS.ok` 增速
与无慢客户端时的**同臂配对差** ≤ 1 帧/分钟（依项目规范：**只比同组配对差，不跨组比绝对值**）。

### M3（P1）原生 Linux 网关（termios + epoll）

**目标环境（写死，防口径漂移）**：原生 Ubuntu 22.04 LTS（glibc + systemd）；验证载体为已有 VM，
产品形态为实体工控机 / 厂商 BSP 的嵌入式 Linux。**WSL2 不在运行环境清单内。**

#### T3.1 分步实施（顺序即风险控制）

| 步 | 内容 | 新代码量 |
|---|---|---|
| **S1** | **Linux TCP 上游模式实跑**（零新代码，纯验收） | 0 |
| S2 | `--serial` 的 Linux 分支：termios + 端口识别 | 小 |
| S3 | POSIX 侧事件循环换 epoll（**依赖 T1.1 已完成**） | 中 |
| S4 | VM 上重跑 `vm_realdevice_e2e.sh` 同套判据（脚本加 `GATEWAY=linux` 开关） | 0 |

- **S1 必须先做**：这是纯证伪动作。项目历史上最贵的 bug 即在此带——`select()` 的 `nfds` 在 Windows 被忽略、
  POSIX 必须为 `max_fd+1`，传错则"连接正常、`dataUp()==true`、零字节"。当前 L201 的
  `static_cast<int>(nf)` 静态看是对的，**但必须实测，不得靠读代码确认结论**。
- **S2 细节**：`open(path, O_RDWR | O_NOCTTY)` + `tcgetattr/tcsetattr`；`cfmakeraw`；
  `cfsetispeed/ospeed(B115200)`；`c_cflag |= CREAD|CLOCAL`；`VMIN=0, VTIME=1`（100ms 有界读，
  让"无数据"成为可读事件而非挂死）。`normalizePort` 的 POSIX 分支识别 `/dev/tty{ACM,USB,S}*`，
  **不做** `COM4→/dev/ttyS3` 伪映射。部署说明须含 `dialout` 组与 `udev` 固定别名（防热插拔节点漂移）。
- **S3 细节**：`epoll_create1(EPOLL_CLOEXEC)`；tty / listener / client 注册 `EPOLLIN | EPOLLET`；
  client 出向非空时 `EPOLL_CTL_MOD` 加 `EPOLLOUT`，排空后**摘除**（否则忙轮询）。
  ET 的前置义务：fd 必须非阻塞、每事件循环处理至 `EAGAIN`、`accept4(SOCK_NONBLOCK)`、
  `EPOLLHUP|EPOLLERR` 走清理路径。Windows 侧 select 腿**原样保留**。

**验收**：Linux 网关 + VM 桥 + gRPC 三者同场；`vm_realdevice_e2e.sh` 六项检查全绿
（`/dmp/frames` 有真帧、`/diagnostics` `crc_err=0`、发布 QoS `BEST_EFFORT` **实测**非推断、
`set_rule` 后网关侧独立回读、非法区间被拒、`selftest healthy=True`）。

**收益定位（不得夸大）**：G3 的价值 = 部署形态成立 + 去掉轮询节拍 + **ET 从机制上强制出向队列正确**；**不含吞吐主张**。

### M4（P2）归因与时基

#### T4.1 分段丢弃计数 + 单调时基

- `STATS` 三字段扩为四段：`tty_overflow`（驱动层丢）/ `ring_drop`（网关环满）/ `queue_drop`（客户端队列丢）
  / 桥侧 `bridge_dropped` 保持独立。
- 帧 `stamp`：`system_clock` → `steady_clock` + 启动时一次性 epoch 锚点；`Sample` 增单调时戳字段，落库两列都存。
  **关闭 ADR-001 遗留项**（"未做时区/单调钟区分，跨机接真板时需重审"）。

### M5（P2）一台 PC 多台仪器

#### T5.1 多路上游

- `--serial <port> <device_id>` **可重复**；`std::vector<SerialUpstream>{ port, deviceId, Acquisition,
  sampleRing, alarmRing }`，每设备独立解码内核与计数。
- 文本 API 增设备维度：`STATS [dev]` / `RULES [dev]` / `SUBSCRIBE [dev]`，**缺省 = 全部（向后兼容）**，
  不破坏现有 Agent 与 e2e 脚本。
- **RAW 定界取舍（决策已定，不摇摆）**：**每设备一个监听端口**（9100/9101/…），**不**在字节流里加 device 信封。
  代价：端口数随设备数线性增长，机队 ≤10 台可接受；超出须以独立 ADR 重新论证带类型的多路复用封装。
- 桥侧无需改动（per-device 前缀已就绪）。

### 5.2 新增 / 变更风险条目

| ID | 风险 | 成因 | 控制措施 |
|---|---|---|---|
| **R-009** | 单个慢客户端拖垮全体 → 采集侧真丢字节 | `sendAll` 阻塞于共享事件循环 | 有界出向队列 + 失能踢除（**SR-014**）；三段丢弃计数可归因（SR-014 / G5） |

### 5.3 文档同步动作

1. `docs/IEC62304-软件生命周期与风险管理.md` §1 第 28 行"部署/运行环境"**拆为两栏**：
   - **开发/验证环境**：Windows 10/11 + MinGW（Qt 6.10.0 mingw_64）；WSL2 Ubuntu（**仅构建 / 工具链沙箱**）；VM Ubuntu 22.04 + ROS2 Humble。
   - **目标运行环境**：Windows 10/11 IoT Enterprise LTSC；原生 Ubuntu 22.04 LTS / 信创发行版（银河麒麟、统信 UOS）；厂商 BSP 嵌入式 Linux。**WSL2 不作为交付运行环境**（不可论证 POUD/SOUP）。
2. 新增 **ADR-004：事件循环分平台实现（select-on-Windows / epoll-on-Linux），拒绝最小公倍数抽象**
   —— 须含"epoll 非性能动机"的诚实说明与失效条件。
3. 新增 **ADR-005：多设备以端口定界，不引入帧信封** —— 含被否方案（加 device 字段、rosbridge、共享内存）。
4. 实施中的踩坑继续沉淀到 `docs/经典Bug素材录.md`（延续 B-xx 编号）。本轮候选：

### 5.4 简历 / 面试口径调整

## 8. 验收与度量规范（全项目统一口径，本方案不得例外）

1. **每条改动必须附能证伪的判据**，无断言即视为未交付（DoD 四件套：可编译 / 可跑 / 有断言证据 / 文档回填）。
2. **验收脚本的结论行必须由本轮数据现算**，禁止写死（已记录教训：脚本自己的结论行会在数据反对它时照样打印）。
3. **全称数字必须带样本量**；性能 A/B **只能比同组配对差**，跨组绝对值比较无效。
4. **文档化之前先实测**：不得把未经测量方向的设计意图写进注释或文档（已记录 QoS 矩阵方向记反的教训）。
5. **取证手段本身要可信**：`timeout` 杀进程导致的缓冲丢失、`head` 截断造成的"对端没回应"假象，都必须在脚本里规避并注明。
6. **验证与确认分存不互冒**：验证（东西做对了吗）= 断言 + CI 门禁；确认（做对东西了吗）= 端到端场景。
