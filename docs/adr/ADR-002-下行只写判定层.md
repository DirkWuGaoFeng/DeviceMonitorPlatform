# ADR-002：ROS2 下行写路径——只写"判定层"，不进测量链路与控制回路

- **状态**：Accepted（2026-09-29，`set_rule` 已在 VM 端到端实测）
- **相关**：`include/dmp/acquisition.h`、`include/dmp/service_proto.h`、`src/gateway_service.cpp`、
  `ros2/dmp_ros2_bridge`、`tests/test_service_proto.cpp`、`ros2/README.md`

## 背景

桥只上行（遥测）时价值有限；接上 ROS2 的自然冲动是"也把控制下发进去"。但 DMP 的定位是
**医疗上位机数据采集与监控**，IEC 62304 语境下"能写什么"必须比"能写多方便"先想清楚。

现有事实：`gateway_service` 是**纯只读**的——蜂鸣、告警确认这些动作都在 Qt 端；
网关能读的有 `STATS/ALARMS/HISTORY/RULES`，能做的只有订阅 `RAW`。要下发"停机/蜂鸣"必须改固件。

## 决策

**下行只开放一类写操作：告警阈值（判定层）下发。**

- 协议面新增 `RULES`（回读）与 `RULE <type> <low> <high> [msg]`（幂等下发，同类型覆盖）
- 服务面 `set_rule` / `get_rules` / `selftest`，其中 `selftest` 严格只读
- 写路径落在 `Acquisition::setRule`：**只改告警判定，不触碰解码/采样链路**
- 服务端校验后拒绝：`low >= high`、非有限数（`isfinite`）、类型越界、畸形数值 token
- `get_rules` 回显的是**服务端实际生效值**（含默认文案），不是调用方声称值
- 网关每次应用都 `printf` 审计行，形成可采集的服务端记录

## 理由与权衡

- 选阈值而不是选蜂鸣器：**零固件风险**就能演示"配置类写入 vs 只读诊断"的安全分级差异。
  写判定层最坏后果是"误告警/漏告警"（可用回读+周期核对发现）；写执行器最坏后果直接作用在病人身上。
- 幂等（同 kind 覆盖）使"重发一次"不引入新状态，配置面因此可安全重试与对账。
- 双连接：数据面 `RAW` 字节流与控制面文本应答**分两条 TCP**。同一连接混用会让文本应答的字节
  插进帧流里无法定界——这是正确性问题，不是风格问题（详见 `gateway_client.hpp` 文件头注释）。
- 代价：阈值下发后**最长 `rule_refresh_ms`(默认 10s) 才被诊断视图采用**。刻意不做"写完立刻本地缓存生效"，
  因为桥里的缓存不等于网关真相；视图宁可短暂陈旧，也不假装一致。

## 被否决的替代方案

- **写蜂鸣/停机**：需要改固件，把 ROS2 侧写路径接到执行器上，安全等级从"配置"跳到"控制回路"，
  与本项目定位（采集/监控 + 合规文档）不匹配。若未来做，应作为独立 ADR + 独立风险项评审。
- **桥内自存阈值、不回读网关**：省一次往返，但"桥以为的值"与"网关生效的值"会分叉，
  正好掩盖了最需要看见的那类故障（配置未落地）。
- **把 `RULE` 塞进已有 `SUBSCRIBE` 连接**：见上面双连接的理由，否决。

## 影响与验证条件

- 断言证据：`tests/test_service_proto.cpp` **58 项**（含"同一份数据在旧阈值不告警、收紧阈值后必须告警"
  的行为差断言，以及 `stat().ok` 不变以证明解码链路未被写操作污染）；
  `ros2/dmp_ros2_bridge/test/test_rule_mapping.cpp` **62 项**（含 `parseFloatStrict` 拒 `"abc"`→0.0）。
- 端到端证据：`tools/vm_e2e.sh` 中 `set_rule{kind:2,low:45,high:115}` → `accepted=True`，
  随后**从网关侧独立回读** `RULES` 显示 `HR low=45.000 high=115.000`；倒置区间返回
  `accepted=False reason='need low < high'`。
- **失效/重审条件**：一旦开放任何影响执行器或测量值的写操作，本 ADR 立即作废，必须重做安全分级、
  加人工确认与权限模型，并同步更新 IEC 62304 风险表（R-001~006 之外新增项）。
